## 1. 왜 10개만 요청했나

사용자가 "coinfocus 는 색인 요청 하라고 안 했는데 빼먹은 거냐"고 물어서 정리한 내용이다.

**빼먹은 게 아니다.** 어제 sitemap 을 양쪽에 제출했고 그게 본 경로다.
개별 요청은 속도를 앞당기는 보조 수단일 뿐이다.

다만 coinfocus 는 bnguide 와 사정이 다르다.

| | bnguide | coinfocus |
|---|---|---|
| sitemap 주소 수 | 5개 | **697개** |
| 개별 요청 | 5개 전부 가능 | 불가능 (네이버 일일 제한, 구글도 대량 요청 차단) |

sitemap 구성 (2026-08-04 실측):

```
뉴스 기사   635개   ← 언론사 요약. 개별 요청 무의미
목록 페이지  52개   ← sitemap 이 알아서
가이드        7개   ← 우리가 쓴 글 ★
주간 정리     2개   ← 우리가 쓴 글 ★
첫 화면       1개   ★
```

**뉴스 기사 635개는 요청하지 않았다.** 언론사 요약이라 원문이 이미 검색에 잡혀 있고,
구글은 원문 쪽을 보여준다. sitemap 에 넣어둔 건 사이트 규모를 알리는 정도의 역할이다.

> 이 숫자가 "직접 쓴 글을 늘리는 것이 가장 효과적"이라는 조언을 그대로 보여준다.
> **지금 색인 요청할 가치가 있는 페이지가 10개뿐이다.**
> 8/10 부터 주간 정리가 쌓이면 이 목록이 매주 하나씩 늘어난다.

| 검색엔진 | 진행 |
|---|---|
| 네이버 (요청 → 웹 페이지 수집) | **10개 완료** |
| 구글 (서치콘솔 → 색인 생성 요청) | **7개 완료 / 3개 남음** |

구글은 **하루 요청 수 제한**이 있어 7개에서 멈춘 것이고 정상이다. 다음 날 초기화된다.
목록 순서대로 했다면 남은 것은 `06-spot.html`, `weekly/index.html`, `weekly/2026-08-w1.html`.

**급하지 않다.** sitemap 에 다 들어 있어 요청 안 해도 구글이 찾아간다. 며칠 빨라지는 차이다.
