## 겪은 문제와 해결
1. **`.ps1` 이 실행조차 안 됨** — Write 로 만든 파일은 BOM 이 없어 PowerShell 5.1 이
   cp949 로 읽는다. 한글 주석이 깨지며 엉뚱한 줄에서 파싱 에러.
   → UTF-8 **BOM** 으로 다시 저장해서 해결. `.ps1` 을 새로 만들 때마다 해야 한다.
2. **`Join-Path $a $b $c` 실패** — PS 5.1 은 인자 2개까지만 받는다 (PS7 은 됨).
   → `Join-Path (Join-Path $a $b) $c` 로 중첩. GitHub Actions 는 pwsh 7 이라
   양쪽에서 도는 문법만 써야 한다.
3. **토큰포스트 한글 깨짐** — `Invoke-WebRequest` 가 PS 5.1 에서 UTF-8 을 자동 인식 못 함.
   → `HttpWebRequest` + `StreamReader(UTF8)` 로 직접 읽는 `Get-FeedXml` 함수 작성.
4. **`media:content` vs `content:encoded` 충돌** — PowerShell XML 어댑터가 `$item.content`
   로 둘을 구분 못 한다. → `ChildNodes` 를 돌며 `Name` 문자열로 정확히 매칭하는
   `Get-Child` / `Get-ChildText` / `Get-ChildAttr` 사용.

## 인기 순위를 어떻게 매기는가  ★중요

- **주제 겹침** (최대 40점) — 여러 기사가 같은 낱말을 쓸수록 큰 뉴스로 본다

- **사진 있음** (5점)

나중에 구글 애널리틱스 등을 붙이면 이 부분만 실제 조회수로 바꾸면 된다.
`$script:StopWords` 에 흔한 낱말이 들어 있는데, 순위가 이상하면 여기를 먼저 손볼 것.

## 고친 버그
**모든 기사가 "방금"으로 표시되던 문제.** `[datetime]"2026-08-03T04:08:33Z"` 를 쓰면
PowerShell 이 한국 시각(13:08)으로 바꿔버리는데, 이걸 UTC 현재시각과 빼서 음수가 나왔다.
→ `ConvertTo-Utc` 함수(AssumeUniversal + AdjustToUniversal)를 만들어 전부 교체.
지금은 "12분 전 / 15분 전"으로 정상 표시된다.

## 사고: build.ps1 이 3중으로 복사됨
PowerShell 로 `-replace` 일괄 치환을 하다가 파일이 3배로 늘고 285번째 줄에서
문장 중간이 잘렸다. **부분 수정으로 복구하지 말고 전체를 새로 쓰는 게 빨랐다.**
교훈: `.ps1` 을 정규식으로 일괄 치환하지 말고 Edit 로 한 군데씩 고치거나 전체를 다시 쓸 것.

## 또 하나: 서버 정리 명령이 자기 자신을 죽임
`Get-CimInstance ... CommandLine -like '*serve.ps1*'` 로 기존 서버를 찾아 죽였더니,
**그 명령을 실행 중인 셸의 CommandLine 에도 'serve.ps1' 글자가 들어 있어** 자기를 죽였다
(exit 255). → `Where-Object { $_.ProcessId -ne $PID }` 를 반드시 넣을 것.

(프로젝트 폴더에는 안 넣었다 — 한 번 쓰고 끝난 도구)

PDF 구조: `%PDF-1.4`, 본문 스트림은 **ASCII85 + Flate 이중 압축**,
한글은 TrueType 서브셋 + **ToUnicode CMap** 으로 코드→글자 매핑. Identity-H(CID) 아님.

**핵심 함정 — 이거 때문에 몇 시간 날렸다:**
```powershell
if ($ch -eq 'z') { ... }    # 틀림! PowerShell -eq 는 대소문자를 안 가린다
if ($ch -ceq 'z') { ... }   # 맞음
```
ASCII85 에서 `z` 는 "0바이트 4개"를 뜻하는 특수기호다. `-eq` 를 쓰면 데이터에 들어있는
**정상 대문자 `Z`** 까지 특수기호로 처리해서 디코딩 결과가 통째로 어긋나고,
그 뒤 Flate 해제가 조용히 실패해 추출 결과가 0자가 된다. 오류 메시지가 안 뜬다.

그 외 걸린 것:
- `$a85[2..$n]` 슬라이스는 Object[] 라서 MemoryStream 이 못 받는다 → `[Array]::Copy` 로 진짜 byte[] 를 만들 것
- ASCII85 자투리 묶음은 85 를 다섯 번 곱하면 uint32 를 넘는다 → long 으로 누적하고 `-band 0xFFFFFFFF`

## 도메인 (coinfocus.co.kr, 후이즈)
- 후이즈 DNS: A 레코드 4개(185.199.108~111.153) + `www` CNAME → `cho87880148-dotcom.github.io`
- **GitHub Actions 배포에서는 CNAME 파일이 필요 없다** (공식 문서 확인). Settings 값만 쓰인다.
- **로컬 DNS 캐시에 두 번 속았다.** `Resolve-DnsName` 이 "없음"을 반환해서 설정이 틀린 줄 알았는데
  `8.8.8.8` 로 직접 물으니 정상이었다. `ipconfig /flushdns` 후 재조회할 것.
  더 확실한 방법: **DNS 를 우회해 GitHub IP 에 직접 요청**하고 Host 헤더로 도메인을 지정한다.
  ```powershell
  $req = [System.Net.HttpWebRequest]::Create('http://185.199.108.153/')
  $req.Host = 'coinfocus.co.kr'
  ```
- HTTPS 인증서는 자동 발급이며 회색 체크박스는 정상. 이번엔 30분 안에 나왔다.
- 메인 canonical 이 `/index.html` 로 나가 sitemap 의 `/` 와 어긋나던 것을 고쳤다
  (검색엔진이 같은 페이지를 둘로 보고 점수를 나눠 갖는다).

## git 작업 시 반복해서 겪은 것 ★
워크플로가 매 실행마다 `data/articles.json` 을 저장소에 되돌려 커밋한다. 그래서:
- **순서를 지킬 것: 커밋 먼저 → `git pull --rebase` → push.**
  pull 을 먼저 하면 `cannot pull with rebase: You have unstaged changes` 로 막힌다.
- 충돌은 항상 `data/articles.json` 에서 난다. `git checkout --ours` 로 원격 것을 취하고
  `.\build.ps1` 을 다시 돌리면 된다 (링크 기준 병합이라 기사가 사라지지 않는다).

# 6차 작업 — 주간 정리와 자동 집필 (같은 날, 여기까지가 오늘)

## 주간 정리 섹션 신설 (/weekly/)
사용자 질문에서 출발: "직접 쓴 글을 늘리라는 게 정확히 뭘 하라는 건가?"
→ 세 가지(기사에 해석 붙이기 / 주간 정리 / 가이드 추가)를 설명하고 **주간 정리**를 택했다.

- 뉴스 껍데기(`templates/base.html`)를 그대로 써서 같은 사이트로 보이게 했다.
- 글 아래에 그 기간 주요 기사 12건이 `from`~`to` 기준으로 자동으로 붙는다.
  쌓아둔 500여 건이 비로소 재료로 쓰인다.
- **제목 규칙이 핵심이다.** "8월 1주차 요약"은 아무도 검색하지 않는다.
  핵심 사건을 앞에 쓰고 주차는 부제로 뺀다. 이 규칙은 `weekly.json` 주석에도 적어뒀다.
- 첫 글(`2026-08-w1`)은 내가 직접 썼다. 콜드카드 8800만 달러 건이 그 주 최대 사건이었다.

## 발행 요일 — 월요일로 정한 이유
사용자가 "월요일 vs 금요일" 중 뭐가 낫냐고 물었다. 데이터로 답했다.
- 최근 14일 요일별 분포에서 **토요일 28건 > 수(19)·목(20)·금(21)**. 주말이 조용하지 않다.
- 금요일 마감은 주말 이틀을 구조적으로 놓치고, **토·일 급변으로 48시간 만에 틀린 글이 된다.**
- "이번 주 비트코인" 검색은 월요일 아침에 몰린다.
→ **월요일 발행, 직전 주 월~일 전체를 다룬다.**

## 자동 집필 — API 방식에서 Claude Code 방식으로
처음엔 API 한 번 호출(`generate-weekly.ps1`)로 만들었다가, 사용자가
**"1주차 글처럼 쓸 수는 없냐"** 고 물어서 방식을 바꿨다.

핵심 차이는 **조사 여부**였다. 1주차 글을 쓸 때 나는 기사를 검색하고 숫자를 대조했는데,
API 한 번 호출로는 그게 안 된다. 그래서 `anthropics/claude-code-action@v1` 로 교체했다.
자세한 구조는 `CLAUDE.md` 의 "주간 정리 자동화" 참고.

**사용자가 A안(승인 후 발행)을 골랐고, 8월 한 달만 시험해보기로 했다.**
비용 주당 $1~3. 이전 방식($0.45)도 `generate-weekly.ps1` 로 남겨뒀다.

## 워크플로 YAML 이 깨져 있었다 ★ 오늘 가장 위험했던 것
사용자가 "테스트 없이 바로 월요일부터 시작하자"고 해서 점검했는데,
**검토 요청 본문 heredoc 이 `run: |` 블록보다 얕게 들여쓰여 YAML 이 통째로 깨져 있었다.**

그대로 뒀으면 월요일에 **아무 일도 일어나지 않고 오류 알림도 없었을 것이다.**
→ 본문을 `.github/weekly-pr-body.md` 로 분리하고 `--body-file` 로 넘기게 고쳤다.
→ 검증 방법도 확보: `GET /repos/{owner}/{repo}/actions/workflows` 에서 `state: active` 확인.

교훈: **YAML 블록에 긴 본문을 직접 넣지 말 것.** 별도 파일로 빼면 이 문제가 원천적으로 없다.
