## 4. 수동으로 2주차 글을 발행했다

CLAUDE.md 의 "수동 발행 절차"에 순서를 적어뒀다. 실제로 이렇게 했다.

1. `git pull` — 봇이 `data/articles.json` 을 계속 커밋하므로 필수
2. `.\prepare-weekly-context.ps1 -Days 7` → 기사 727건 추림
3. `.github\weekly-instructions.md` 를 읽고 그대로 따라 원고 작성
   - **수치 23항목을 `full.md` 에서 grep 으로 대조**

4. `.\apply-weekly-meta.ps1 -Slug '2026-08-w2' -From '2026-08-05' -To '2026-08-12'`
5. `.\build.ps1` — 통과
6. `git add weekly/` → 커밋 `e0ea76c` → push → 배포 성공 → HTTP 200 확인

### 글 구성 (5개 섹션 + 다음 주에 볼 것)

1. 시세 — 6만5000달러 돌파 시도 네 차례 실패, 마지막 날 CPI 부합으로 6만4045달러 회복
2. 거래가 얼어붙었다 — 무기한 선물 30일 평균 거래량 108억 달러, 2023년 이후 최저 (K33 "동면 순환")
3. 기업들은 팔고 AI로 갔다 — 생산비용 7만4300달러 > 가격 6만4000달러가 매도 이유
4. 콜드카드 41분의 정체 — 2021년 펌웨어 빌드 오류로 개인키 조합 40억 가지로 붕괴 (1주차 후속)

### 이때 알게 된 것 세 가지

- **`apply-weekly-meta.ps1` 은 같은 slug 가 이미 있으면 그냥 건너뛴다.**
  제목을 고치려면 `weekly/weekly.json` 을 직접 Edit 해야 한다. 재실행으로는 안 바뀐다.
- **제목 30자 규칙은 `build.ps1` 이 경고로 잡아준다.**
  처음 쓴 37자 제목("…클래리티법 9월 15일 표결")이 걸려서 30자로 줄였다("…클래리티법 9월로").
- **`git add` 는 `weekly/` 만.** `build.ps1` 이 `data/articles.json` 을 건드리는데 그건 봇 담당이라
  `git checkout -- data/articles.json` 으로 되돌린다. 워크플로도 원래 그렇게 설계돼 있었다.

### 수치 검증에서 일부러 뺀 것

1주차 글에 있던 **공포탐욕지수를 쓰지 않았다.** `full.md` 에 '공포탐욕지수' 표현이 0건이고,

## 5. 기사 보관 상한 — 480 으로 내렸다가 되돌렸다

사용자가 목록이 129쪽까지 늘어난 것을 보고 "40쪽까지만 두고 뒤는 삭제하자"고 요청.

### 알게 된 사실

- **상한 장치는 처음부터 있었다.** `build.ps1` 의 `$KeepMax = 2000`. 1545건이라 아직 발동 전이었다.
- **용량은 문제가 아니었다.** `dist` 28MB / GitHub Pages 한도 **1GB** = 2.8%.
- 480 으로 내려보니 목록 40쪽 / `dist` 8.8MB / sitemap 530개로 줄긴 했다.

### 되돌린 이유 (사용자가 지적)

**하루 수집량이 65~166건이라 480건은 4일치밖에 안 된다.**
`prepare-weekly-context.ps1 -Days 7` 이 이 저장소를 읽으므로 **주간 정리가 7일을 못 채운다.**

날짜 기준(10일치)으로 바꾸는 안을 검토하다가, 사용자가 그대로 두기로 결정.
**`$KeepMax = 2000` 으로 복구했다** (커밋 `1c553bd`). 2000이면 약 18일치라 주간 정리에 여유가 있다.

일별 실측 (2026-08-12 기준):

```
08-12 128건 / 08-11 166건 / 08-10 86건 / 08-09 65건 / 08-08 84건
08-07 100건 / 08-06 105건 / 08-05 100건 / 08-04 119건 / 08-03 132건
```

### 남긴 것 — 주간 정리 링크 기사 보존

상한 변경과 별개로 이 장치는 남겼다. 해가 없고, 2000건에서 잘려나갈 때 필요해진다.

`build.ps1` 4번 항목에서 `weekly/posts/*.html` 을 훑어 `../news/{id}.html` 링크를 모으고,
그 기사는 상한을 넘겨도 버리지 않는다. **버리면 우리가 직접 쓴 글의 링크가 404 가 되기 때문이다.**
상한을 50건까지 낮춰 시험했을 때 밀려난 4건을 정확히 구조하는 것을 확인했다.

- 현재 보존 대상 6건 (2주차 글의 근거 링크). 1주차 글은 수동 링크가 0개다.
- 주간 정리 아래 자동으로 붙는 "그 기간 주요 기사 목록"은 남은 기사에서만 생성되므로
  **알아서 짧아지고 404 가 생기지 않는다.** 위험한 건 본문의 수동 링크뿐이다.
