## 6. SEO 정비 2번 — robots.txt 에 feed.xml 추가

점검에서 나온 개선 목록의 2번 항목입니다.

### 무엇이 문제였나

`feed.xml` 은 원래부터 잘 만들고 있었습니다(항목 30건, 200 응답).
그런데 **robots.txt 에 적어두지 않아 검색엔진에게 알려주지를 못하고 있었습니다.**

```
전:  Sitemap: https://coinfocus.co.kr/sitemap.xml
후:  Sitemap: https://coinfocus.co.kr/sitemap.xml
     Sitemap: https://coinfocus.co.kr/feed.xml      ← 추가
```

**네이버는 sitemap 뿐 아니라 RSS 도 수집 경로로 씁니다.**
이 사이트는 뉴스가 1시간마다 올라오는데 sitemap 만 알려주면 새 기사를 늦게 가져갑니다.
옆 폴더 `test`(bnguide)는 처음부터 둘 다 적어뒀는데 여기만 빠져 있었습니다.

### 고친 곳

`build.ps1` 의 10번 구역(검색엔진용 파일). `robots.txt` 는 파일로 두는 게 아니라
빌드가 만들어내므로 **`dist/robots.txt` 를 직접 고치면 다음 빌드에 날아갑니다.**

```powershell
$sitemapLine = "Sitemap: $baseUrl/sitemap.xml`nSitemap: $baseUrl/feed.xml"
```

### 확인

| 항목 | 결과 |
|---|---|
| BOM 유지 (한글 주석 있어 필수) | `ef bb bf` ✅ |
| 구문 검사 (`Parser::ParseFile`) | 오류 0건 ✅ |
| 빌드 후 `dist/robots.txt` | Sitemap 2줄 ✅ |
| `feed.xml` | 항목 30건 정상 ✅ |

### 5번 — 썸네일 alt ❌ 고치지 않았습니다 (전제가 틀렸습니다)

목록에는 "첫 화면 이미지 58장 중 46장이 `alt=""` 라 화면을 못 보는 이용자에게 아무 정보가 없다"
고 적혀 있었는데, **마크업을 실제로 뜯어보니 사실이 아니었습니다.**

`dist/index.html` 을 훑어 `alt=""` 인 46장이 각각 어디에 들어 있는지 셌습니다.

```
alt="" 46장
  → 기사 제목을 글자로 품은 <a> 안에 있는 것 :  46장
  → 정말로 설명이 없는 것                    :   0장
```

세 자리 전부 이런 구조입니다.

```html
<a class="ticker-item" href="...">[사진]<span>기사 제목</span></a>
<a class="slide"       href="...">[사진]<div class="slide-text"><h3>기사 제목</h3>…</div></a>
<a href="...">          <span class="mini-thumb">[사진]</span><span class="mini-title">기사 제목</span></a>
```

**링크 안에 제목이 이미 글자로 있으면 그 사진은 장식입니다. 이때는 `alt=""` 가 정답입니다.**
여기에 제목을 또 넣으면 화면 낭독기가 **제목을 두 번 읽습니다.** 지금보다 나빠집니다.

게다가 `build.ps1` 783줄에 이 결정이 이미 주석으로 적혀 있었습니다:

```
# (속보 띠·작은 목록의 썸네일은 바로 옆에 제목이 있어 장식이므로 비워둡니다)
```

즉 **누가 실수로 빼먹은 것이 아니라, 알고 비워둔 것**입니다.
제목이 옆에 없는 카드형(`card-thumb`)·본문 사진(`article-thumb`)에는 원래부터 alt 가 들어가 있습니다.

> 교훈 — 목록의 "무엇이" 칸은 숫자만 세서 적힌 것이었습니다(alt="" 46장).
> **그 이미지가 어떤 맥락에 있는지는 세지 않았습니다.** 접근성은 개수가 아니라 맥락입니다.

| 핫링크 차단 | 없음 (레퍼러 없이도 받아짐) |

> 중간에 blockmedia 이미지가 404 로 보였는데 **오판이었습니다.**
> 파일명이 한글이라 `curl` 이 그대로 보내서 난 것이고, 브라우저처럼 인코딩하면 200 입니다.

**사본을 만들지 않기로 한 이유 — 저장소가 감당하지 못합니다.**

```
이미지 있는 기사        1,969건
현재 .git 크기            28MB
사진 평균               100~485KB (WebP 로 줄여도 40~60KB)

지금 것만 받아도        약 100MB
git 은 지운 파일도 영원히 남깁니다 → 1년이면 수백 MB 가 더 쌓입니다
GitHub Pages 는 1GB 가 권장 상한입니다
```

이 사이트는 **1시간마다 기사가 들어옵니다.** 사본을 뜨기 시작하면 저장소가 단조 증가하고,
빌드·배포 시간도 같이 늘어납니다. 얻는 것(사진이 깨질 위험 대비)에 비해 대가가 큽니다.
저작권 면에서도 남의 사진을 우리 서버에 복제해 두는 쪽이 불리합니다.

**대신 진짜 위험만 막았습니다 — `assets/js/main.js` 에 자리표시 대체를 넣었습니다.**

사본을 안 뜨기로 한 이상 "언론사가 사진을 내리면 어떻게 되나"가 남습니다.
확인해보니 **대비가 전혀 없었습니다**(`onerror` 0건). 깨진 이미지 아이콘이 그대로 보였을 것입니다.
기사에 원래 사진이 없을 때 쓰는 **₿ 표시로 바꿔 끼우도록** 했습니다.

```
img 의 error 는 위로 전파되지 않습니다  → addEventListener 의 세 번째 인자를 true (캡처)
스크립트가 </body> 앞에서 실행됩니다     → 이미 실패가 끝난 것은 못 듣습니다
                                        → complete && naturalWidth===0 으로 한 번 훑습니다
```

이 두 함정을 빼면 **아무것도 안 잡힙니다.** 주석에도 적어뒀습니다.
